# 바로잡길 제품 요구사항

- 문서 상태: MVP 기획 기준
- 최종 갱신: 2026-09-06
- 대상: 제품, 디자인, 프론트엔드, 백엔드, AI 개발

## 1. 제품 개요

바로잡길은 블랙박스 영상이나 사진 속 교통법규 위반 의심 장면을 찾아 신고 준비를 돕는 서비스다. 긴 영상을 직접 탐색하고 차량번호·시각·장소를 확인하며, 위반 유형과 필요한 증거를 검토하고 신고 문장을 작성하는 부담을 줄인다.

서비스는 신고 자료를 정리하는 보조 도구다. AI는 위법 여부를 확정하지 않으며, 최종 내용 확인·판단·안전신문고 제출은 반드시 사용자가 직접 한다.

## 2. 해결하려는 문제

사용자는 교통법규 위반 장면을 촬영하고도 다음 과정의 번거로움 때문에 신고를 포기한다.

- 긴 영상에서 위반 장면 찾기
- 차량번호, 발생 시각, 장소 확인하기
- 가능한 위반 유형과 근거 검토하기
- 신고에 필요한 증거가 영상에 담겼는지 확인하기
- 객관적인 신고 문장 작성하기
- 운전이 끝난 뒤 신고할 시점을 기억하고 다시 준비하기

## 3. 제품 목표

- 긴 영상에서 검토할 위반 의심 장면을 빠르게 찾게 한다.
- 신고 핵심정보와 증거 상태를 한 흐름에서 검토하게 한다.
- AI 제안과 사용자 확정값을 구분하고 모든 신고용 값을 수정할 수 있게 한다.
- 선택한 핵심 미디어와 신고 문장을 하나의 신고 패키지로 정리한다.
- 운전 중 조작을 유도하지 않도록 신고 버튼 활성 시점을 미룰 수 있게 한다.
- 별도 동의를 받은 비식별 집계 데이터로 교통위험 정보를 제공한다.

## 4. 핵심 원칙

### 4.1 AI와 사용자 책임

- AI는 위법 여부를 확정하지 않는다.
- 결과 화면에는 `예상 위반 유형`과 `AI 참고 분석`이라는 표현을 사용한다.
- AI가 확인하지 못한 값을 추측해서 채우지 않고 `확인 필요`로 표시한다.
- 신고에 쓰이는 차량번호, 시각, 장소, 위반 유형, 핵심 구간, 신고 문장은 사용자가 확인하고 수정할 수 있어야 한다.
- AI가 낸 원래 결과·근거·신뢰도와 사용자 수정값은 출처가 섞이지 않도록 구분한다.
- 최종 판단과 신고는 사용자에게 있음을 중요한 결정 화면마다 알린다.

### 4.2 신고 경계

- 안전신문고에 자동으로 접수하거나 자료를 자동 전송하지 않는다.
- 사용자의 명시적인 클릭 없이 외부 사이트를 열지 않는다.
- 안전신문고로 이동한 사실을 신고 완료로 간주하지 않는다.
- 안전 지연 신고는 `신고 버튼이 활성화되는 시점`만 예약하며, 신고 자체를 예약하지 않는다.

### 4.3 개인정보

- 원본 영상·사진은 공개하지 않는다.
- 차량번호는 공개 화면과 교통위험지도에 절대 표시하지 않는다.
- 지도 제공 동의는 서비스 이용 동의와 분리한다.
- 지도에는 개별 사건이 아니라 재식별 위험을 낮춘 집계 결과만 표시한다.

## 5. MVP 범위

### 5.1 포함

- 블랙박스 영상 또는 사진 업로드
- 전체 영상에서 위반 의심 구간 탐색
- 복수 후보의 타임라인 표시와 후보 선택
- 핵심 영상 구간 확인 및 조정
- 차량번호, 발생 시각, 장소 추출과 사용자 수정
- 예상 위반 유형, AI 판단 근거, 신뢰도 표시
- 위반 유형별 증거 충족도와 부족한 증거 안내
- 신고 패키지와 신고 문장 생성 및 수정
- 안전 지연 시점 설정, 변경, 취소와 버튼 활성화
- 안전신문고 공식 경로로 사용자 직접 이동
- 별도 동의 데이터의 비식별 교통위험지도 집계
- 실제 AI API 연결 전 결정적 mock 분석 데이터 사용

### 5.2 우선 지원 위반 유형

1. 신호위반
2. 중앙선 침범
3. 위험 끼어들기
4. 판단 불가

`판단 불가`는 근거가 부족하거나 AI 지원 범위 밖일 때 사용하는 안전한 결과 상태이며 위반 유형은 아니다.

### 5.3 MVP 제외

- 위법 여부 또는 법률적 신고 요건의 확정
- 안전신문고 자동 제출과 접수 결과 자동 수집
- 범칙금·과태료·신고 수리 가능성 보장
- 실시간 주행 중 촬영이나 조작을 유도하는 기능
- 우선 지원 3종 외 위반의 상세 증거 진단
- 원본 미디어, 차량번호, 정밀 위치의 공개
- 실제 AI API 연결
- 네이티브 모바일 앱

## 6. 핵심 사용자 흐름

1. 사용자가 영상 또는 사진을 업로드한다.
2. 서비스가 업로드 및 분석 상태를 보여준다.
3. 영상이면 AI가 전체 영상을 검사해 위반 의심 후보를 찾는다. 사진이면 단일 장면 검토로 이동한다.
4. 여러 후보가 있으면 시간순 타임라인으로 보여준다.
5. 사용자가 신고할 후보와 핵심 구간을 선택한다.
6. 차량번호, 발생 시각, 장소를 확인하고 필요하면 수정한다.
7. 예상 위반 유형, AI 참고 분석, 신뢰도를 확인하고 유형을 확정 또는 수정한다.
8. 선택한 유형의 증거 충족도와 부족한 항목을 확인한다.
9. 핵심 미디어와 신고 핵심정보, 신고 문장이 포함된 신고 패키지를 만든다.
10. 사용자가 모든 신고용 내용을 최종 확인하고 수정한다.
11. 사용자가 안전 지연 시점을 설정한다.
12. 설정 시점 이후 안전신문고 이동 버튼이 활성화된다.
13. 사용자가 안전신문고에서 직접 첨부하고 신고한다.
14. 별도 동의가 있으면 사용자 확인을 거친 비식별 데이터가 위험지도 집계 후보가 된다.

## 7. 기능 요구사항

### FR-01. 미디어 업로드

사용자는 블랙박스 영상 또는 사진을 선택하고 업로드할 수 있어야 한다.

필수 동작:

- 선택한 파일명, 종류, 미리보기를 보여준다.
- 업로드 전 파일을 교체하거나 제거할 수 있다.
- 형식, 크기, 영상 길이, 손상 여부를 검증하고 해결 가능한 오류 문구를 제공한다.
- 업로드 진행률, 취소, 실패, 재시도 상태를 제공한다.
- 원본이 공개되지 않는다는 안내를 보여준다.
- 사진은 타임라인 없이 단일 후보로 검토한다.

수용 기준:

- 유효하지 않은 파일로 분석을 시작할 수 없다.
- 업로드가 완료되지 않은 파일을 분석 완료로 표시하지 않는다.
- 업로드 오류에는 내부 저장 경로나 민감정보가 포함되지 않는다.
- mock 단계에서도 실제 개인정보가 담긴 fixture를 저장소에 추가하지 않는다.

### FR-02. 위반 의심 구간 탐색

영상 전체를 분석하여 검토할 후보를 0개 이상 생성한다. 각 후보에는 다음 정보가 포함된다.

- 시작·종료 오프셋
- 대표 이미지
- 예상 위반 유형 또는 판단 불가
- 후보 탐지 신뢰도
- 관찰 사실 중심의 짧은 탐지 사유

후보 탐지 신뢰도와 위반 유형 분류 신뢰도는 서로 다른 값으로 취급한다.

수용 기준:

- 복수 후보는 시간순으로 정렬한다.
- 후보가 없으면 별도의 `의심 장면을 찾지 못함` 상태와 다음 행동을 안내한다.
- 분석 실패와 후보 없음은 구분한다.
- 실패 시 안전하게 재시도할 수 있다.
- mock 분석임을 사용자가 실제 AI 결과로 오인하지 않게 표시한다.

### FR-03. 후보 타임라인과 장면 선택

- 후보의 시점, 썸네일, 예상 유형, 신뢰도를 모바일 타임라인으로 비교할 수 있어야 한다.
- 선택된 후보를 시각적·텍스트로 명확히 표시한다.
- 후보를 누르면 해당 구간으로 이동하고 전후 문맥을 재생할 수 있어야 한다.
- 사용자는 핵심 영상 시작·종료 지점을 조정할 수 있어야 한다.
- 후보나 구간을 바꾸면 이후 핵심정보, 증거 분석, 패키지에 변경이 반영되어야 한다.

MVP에서는 신고 패키지 하나에 사용자 확정 후보 하나를 사용한다.

### FR-04. 신고 핵심정보 추출과 수정

다음 값을 추출하고, 값별 상태·출처·신뢰도를 보여준다.

- 차량번호
- 발생 날짜와 시각 및 시간대
- 장소: 사용자 표시용 주소와 내부 좌표

가능한 출처는 영상 자막 OCR, 번호판 OCR, 파일 메타데이터, 위치 분석, 사용자 입력이다.

수용 기준:

- 모든 신고용 값을 수정하거나 비울 수 있다.
- 찾지 못했거나 충돌하는 값은 `확인 필요`로 표시한다.
- 사용자가 수정한 값은 단계 이동과 새로고침 뒤에도 유지된다.
- 사용자 확정값이 신고 문장과 패키지에 반영된다.
- AI 원본값을 사용자 확정값으로 덮어써 출처를 잃지 않는다.
- 차량번호와 정밀 위치를 URL, 공개 로그, 지도 집계 입력에 넣지 않는다.

### FR-05. 예상 위반 유형과 AI 참고 분석

선택한 후보에 대해 다음을 보여준다.

- `예상 위반 유형`
- `AI 참고 분석`
- 유형 분류 신뢰도
- 필요한 경우 다른 가능성 또는 판단 불가

수용 기준:

- `위반 확정`, `불법 차량`처럼 법적 결론을 암시하는 표현을 쓰지 않는다.
- 근거는 영상에서 관찰 가능한 사실과 불확실성을 함께 설명한다.
- 사용자는 신고에 적용할 위반 유형을 지원 3종 또는 판단 불가 중에서 직접 선택할 수 있다.
- 사용자가 유형을 바꾸면 해당 유형의 증거 체크리스트를 다시 계산한다.
- AI 신뢰도는 읽기 전용 원본값으로 보존하고 사용자 선택과 구분한다.

### FR-06. 위반 유형별 증거 충족도

증거 항목 상태는 `충족`, `부분 충족`, `미충족`, `판단 불가`, `해당 없음` 중 하나다. 각 항목에는 상태의 근거와 관련 영상 시점을 함께 제공할 수 있어야 한다.

MVP 참고 체크리스트:

| 예상 유형 | 관찰 항목 예시 |
| --- | --- |
| 신호위반 | 적용 신호 상태, 정지선 또는 교차로 진입 장면, 대상 차량 식별 연속성, 전후 문맥 |
| 중앙선 침범 | 중앙선 식별, 차선을 넘는 이동 궤적, 대상 차량 식별 연속성, 도로 상황과 예외 가능성 |
| 위험 끼어들기 | 차선과 이동 경로, 전후 차량 간격, 급격한 진입 정황, 전후 문맥 |

이 체크리스트는 법적 요건의 확정 목록이 아니다. 출시 전 관련 규정과 공식 신고 안내를 별도로 검토하고 규칙 버전을 관리한다.

수용 기준:

- 실제로 보이지 않는 항목을 충족으로 표시하지 않는다.
- 부족한 경우 무엇이 보이지 않거나 불명확한지 설명한다.
- 전체 상태는 `충분해 보임`, `추가 확인 필요`, `부족`, `판단 불가`처럼 참고 표현을 사용한다.
- 증거 상태를 신고 가능·불가능 또는 처벌 가능성으로 변환하지 않는다.

### FR-07. 신고 패키지와 신고 문장

사용자 확정값을 기준으로 다음을 하나의 검토 가능한 패키지로 구성한다.

- 선택한 핵심 영상 구간 또는 사진
- 차량번호
- 발생 시각
- 장소
- 예상 위반 유형
- 증거 충족도 요약
- 관찰 사실 위주의 신고 문장

수용 기준:

- 확인되지 않은 사실을 신고 문장에 새로 만들지 않는다.
- 누락값을 숨기지 않고 확인 필요 상태로 보여준다.
- 사용자가 모든 텍스트와 신고용 필드를 수정할 수 있다.
- 문장 재생성이 기존 사용자 수정 내용을 덮어쓸 때는 먼저 확인을 받는다.
- 패키지 생성, 복사, 다운로드만으로 신고 완료 상태가 되지 않는다.
- 사용자 최종 확인 전 외부 전송이 일어나지 않는다.

### FR-08. 최종 검토

- 핵심 미디어, 차량번호, 시각, 장소, 유형, 증거 요약, 신고 문장을 한 흐름에서 검토할 수 있어야 한다.
- AI 제안, 사용자 수정, 사용자 확인 완료 상태를 구분한다.
- 확인하지 않은 필드와 부족한 증거를 명확히 알린다.
- 진행 전 `AI 분석은 참고 정보이며 최종 판단과 신고는 사용자가 직접 한다`는 안내를 표시한다.

### FR-09. 안전 지연 신고

사용자는 안전신문고 이동 버튼이 활성화될 미래 시점을 설정·변경·취소할 수 있어야 한다.

수용 기준:

- 예약 시각과 남은 시간을 보여준다.
- 예약 전에는 안전신문고 이동 버튼을 비활성화한다.
- 예약 시각 이후에는 서버 기준 시각으로 버튼을 활성화한다.
- 사용자 기기의 시계만으로 활성 여부를 결정하지 않는다.
- 예약 시각은 검증된 신고 가능 기한보다 앞서야 하며, 기한을 넘는 선택은 막고 이유를 설명한다.
- 신고 가능 기한이 지나면 만료 상태를 표시한다.
- 예약 시각이 되어도 자동 제출, 자동 외부 이동, 자동 첨부가 일어나지 않는다.
- `버튼 활성`과 `법적으로 신고 가능함`을 같은 의미로 표현하지 않는다.

정확한 신고 가능 기간과 예외는 구현 전에 공식 근거와 정책 책임자를 정해 검증해야 하며 코드에 영구 상수로 고정하지 않는다.

### FR-10. 안전신문고 수동 이동

- 활성화된 버튼은 검증된 안전신문고 공식 웹 경로 또는 지원되는 공식 앱 경로로 연결한다.
- 클릭 전 외부 서비스로 이동하며 사용자가 직접 첨부·제출해야 함을 알린다.
- 사용자의 클릭 없이 창을 열거나 자료를 전송하지 않는다.
- 외부 이동 여부와 실제 신고 완료 여부를 별도 상태로 취급한다.
- 실제 신고 완료는 사용자가 명시적으로 기록하는 경우에만 서비스 내부 상태로 남긴다.

### FR-11. 교통위험지도와 동의

사용자는 신고 지원과 별개로 지도 집계 제공에 선택적으로 동의할 수 있어야 한다. 동의하지 않아도 핵심 신고 지원 기능을 사용할 수 있어야 한다.

지도 집계에 사용할 수 있는 값:

- 일반화된 공간 격자 또는 도로 구간
- 넓은 시간 구간
- 사용자가 확인한 지원 위반 유형
- 집계 건수 또는 설명 가능한 위험 지표

지도 파이프라인과 공개 결과에 포함할 수 없는 값:

- 차량번호와 번호판 이미지
- 원본 또는 핵심 영상·사진
- 얼굴과 음성
- 사용자 식별자
- 원본 파일 URL과 저장 경로
- 개별 사건을 역추적할 수 있는 정밀 위치·시각 조합

수용 기준:

- 별도 동의가 없으면 지도 집계 파이프라인에 데이터를 보내지 않는다.
- 동의 시점과 정책 버전을 기록하고 철회 방법을 제공한다.
- 공개 지도는 익명화된 개별 점이 아니라 집계 셀만 조회한다.
- 재식별 가능성이 있는 소수 집계는 숨긴다.
- 지도 UI에는 `확정 위반 지도`가 아닌 비식별 참고 집계임을 설명한다.

### FR-12. 상태와 오류 복구

다음 상태를 명시적으로 구분한다.

- 업로드 전, 업로드 중, 업로드 실패
- 분석 대기, 분석 중, 분석 완료, 후보 없음, 분석 실패
- 후보 선택, 상세 검토, 패키지 준비
- 지연 대기, 버튼 활성, 신고 기한 만료
- 삭제됨

수용 기준:

- 처리 중 빈 화면을 표시하지 않는다.
- 오류마다 재시도, 파일 교체, 직접 입력 등 가능한 복구 행동을 알려준다.
- 재시도는 중복 분석 작업이나 중복 패키지를 만들지 않아야 한다.
- 오류 메시지와 관측 로그에 차량번호, 원본 URL, 정밀 위치를 넣지 않는다.
- 사용자의 수정 내용은 예기치 않은 새로고침이나 단계 이동으로 사라지지 않아야 한다.

- 예상 위반 유형
- AI 참고 분석
- AI가 확인한 내용
- 사용자의 확인이 필요합니다
- 증거가 충분해 보입니다
- 추가 확인이 필요합니다
- 신고 자료 준비 완료
- 안전신문고에서 직접 신고하기

- 위반 확정
- 불법 차량
- 신고 가능 보장
- 처벌 가능
- 신고가 자동 접수됩니다
- AI가 법적으로 판정했습니다

핵심 안내 문구:

## 10. 비기능 요구사항

### 10.1 모바일과 접근성

- 모바일 세로 화면에서 핵심 흐름을 완료할 수 있어야 한다.
- 주요 조작은 충분한 터치 영역을 갖고, 긴 결과는 단계 또는 접을 수 있는 구역으로 나눈다.
- 상태는 색상만으로 구분하지 않는다.
- 키보드 탐색, 명확한 포커스, 입력 레이블과 오류 연결을 제공한다.
- 동영상 후보와 증거 상태를 텍스트로도 이해할 수 있게 한다.

### 10.2 보안과 개인정보

- 원본 미디어, 차량번호, 정밀 위치, 발생 시각을 민감정보로 취급한다.
- 전송 및 저장 중 암호화, 사용자별 접근 통제, 짧게 만료되는 미디어 접근 URL을 사용한다.
- 업로드 파일의 선언된 형식뿐 아니라 실제 형식·크기·길이도 서버에서 검증한다.
- 보관 기간, 즉시 삭제, 동의 철회 정책을 출시 전에 확정한다.
- 민감정보를 URL, 로그, 오류 추적, 제품 분석 이벤트, 공개 캐시에 기록하지 않는다.

### 10.3 유지보수성과 신뢰성

- TypeScript strict 설정을 유지한다.
- UI, 도메인 규칙, 저장소, 외부 AI를 분리하고 mock과 실제 구현이 같은 계약을 사용한다.
- 분석 작업과 외부 콜백은 멱등성을 가져야 한다.
- 분석·신고·동의 상태를 명시적인 상태와 허용된 전이로 관리한다.
- 모델, 프롬프트, 증거 규칙, 신고 기간 정책의 버전을 결과와 함께 기록한다.

## 11. 핵심 수용 시나리오

### A. 복수 후보 영상

사용자가 영상을 업로드하면 복수 후보가 시간순으로 표시된다. 사용자가 후보와 구간을 고르고 핵심정보·유형·문장을 수정하면 동일한 값으로 패키지가 생성된다. 지연 시각 전에는 버튼이 비활성이고, 이후에는 공식 안전신문고로 이동하되 자동 제출은 발생하지 않는다.

### B. 후보 없음

후보 없음과 분석 실패를 구분해 보여준다. 위반 유형이나 차량번호를 임의 생성하지 않고, 사용자가 다른 파일을 선택하거나 직접 영상을 검토할 다음 행동을 제공한다.

### C. 정보 또는 증거 부족

확인하지 못한 차량번호·장소와 부족한 증거를 구체적으로 표시한다. 불완전함을 숨기지 않으며 사용자가 직접 보완하거나 진행 여부를 판단한다.

### D. 사진

타임라인 없이 단일 장면 검토로 이동한다. 사진만으로 확인할 수 없는 전후 문맥은 판단 불가 또는 부족으로 표시한다.

### E. 지도 제공 비동의

신고 지원 흐름은 동일하게 사용할 수 있으며 해당 데이터는 지도 집계 입력으로 전달되지 않는다.

## 12. 제품 지표

개인정보를 수집하지 않는 이벤트만 사용해 다음을 관찰한다.

- 업로드 시작 대비 완료율과 실패 사유 범주
- 분석 완료율, 후보 없음 비율, 분석 소요 시간
- 후보 선택부터 패키지 준비까지 걸린 시간
- 핵심정보와 예상 유형의 사용자 수정률
- 증거 부족 안내 후 사용자의 다음 행동
- 지연 기능 설정·취소·버튼 활성 비율
- 안전신문고 이동 클릭률과 사용자 자가 기록 완료율
- 별도 지도 제공 동의율

차량번호, 신고 문장, 정확한 좌표, 미디어 식별자와 URL은 분석 이벤트 속성으로 수집하지 않는다.

## 13. 구현 전 확정할 정책

- 지원 미디어 형식, 최대 크기와 최대 길이
- 로그인 필요 여부와 비회원 데이터 유지 범위
- 원본·파생 미디어·분석 결과의 보관 기간과 삭제 UX
- 신고 가능 기간의 공식 기준, 예외, 정책 갱신 책임자
- 안전 지연 기본값과 사용자 지정 범위
- 지연 상태의 재접속·다른 기기 동기화 및 알림 범위
- 안전신문고 웹 링크와 앱 딥링크의 플랫폼별 동작
- 신고 패키지의 다운로드 형식과 실제 영상 자르기 방식
- 위치 추출 우선순위와 수동 지도 검색 방식
- 지도 공간·시간 집계 단위, 최소 공개 건수, 위험 지표 산식
- 동의 철회 시 이미 생성된 집계값의 처리
- 한 원본에서 여러 신고 패키지 생성 지원 여부
- 법률·개인정보·AI 외부처리 검토 책임자와 승인 절차
